## 1. 배경 및 문제 정의

캠퍼스는 처음 가는 건물, 붙어 있는 건물, 층이 어긋난 건물이 많아 길을 잃기 쉽습니다. 인터뷰한 9명(P1–P9)은 대부분 건물이나 강의실을 찾다가 헤맨 경험을 이야기했습니다. 수업에 늦은 경우(P6)도 있었고, 목적지 건물을 오해해 당황한 경우(P4)도 있었습니다.

인터뷰에서 반복된 문제를 여섯 가지로 정리했습니다.

| 번호 | 문제 | 근거 | 인터뷰 발언 (요약) |
|---|---|---|---|
| ① | 내 위치와 방향을 모른다 | P1, P4, P6 | P1: 자신이 있는 곳과 가야 할 곳이 어디인지 모르는 것이 가장 답답했다.<br>P6: "내 위치가 정확히 어디인지 모르겠다는 점입니다."<br>P4: 있던 건물이 목적지 건물이 아니어서 당황했다. |
| ② | 건물 내부 층·호수 구조를 알기 어렵다 | P3, P5, P8 | P3: 안내판에 같은 층이라고 나와 있었지만 109호 옆에 110호가 없어 다른 쪽으로 돌아가야 했다.<br>P5: 시간표의 B101에서 B를 못 보고 101호로 갔다.<br>P8: 건물이 두 덩어리인데 4층에만 연결다리가 없어 다시 내려갔다. |
| ③ | 건물 간 연결 통로와 지름길을 모른다 | P5, P8 | P5: 건물끼리 연결된 지름길이 있을 것 같은데 몰라서 지도만 따라 돌아갔다.<br>P8: 지도에 안 나오는 지름길을 찾으면 기분이 좋다. |
| ④ | 지도와 실제 풍경이 연결되지 않는다 | P2, P9 | P2: 길이 넓은데 지도에 아무것도 표시되어 있지 않아 어디가 어딘지 알기 어려웠다.<br>P9: 지도에 표시된 위치가 실제로 어디쯤인지 감이 안 오고, 지도에서는 가까워 보이는데 실제로는 멀다. |
| ⑤ | 일반 지도 앱은 캠퍼스 안을 자세히 알려주지 않는다 | P5, P6, P8 | P6: 학교 이름을 치면 학교 위치는 알려주지만 캠퍼스 안의 건물들은 알려주지 않는다.<br>P5: 건물 번호가 아니라 건물 이름을 쳐야 잘 나온다.<br>P8: 몇 층인지, 건물 안에서 방이 어디인지까지는 알려주지 않는 경우가 많다. |
| ⑥ | 지도 정보가 믿을 만한지 알 수 없다 | P6 | P6: 그 지도가 언제 만들어진 건지 몰라 최신 정보가 맞는지 확신할 수 없었다. |

### 기존 대안의 한계

- **사람에게 묻기:** P1은 급해서 사람에게 물었지만 처음 물어본 사람도 장소를 몰라 한두 번 더 물어야 했습니다.
- **에브리타임 지도:** P6은 스크랩해 둔 지도를 찾아가 봐야 했고, 지도가 언제 만들어졌는지 알 수 없었습니다.
- **네이버 지도·카카오맵:** 캠퍼스 건물 안쪽 정보가 부족하고(P6, P8), 건물 간 연결 구조는 알 수 없었습니다(P5).

> **문제 정의** 캠퍼스 이용자는 "지금 내 위치", "건물 안의 구조", "주변 단서와 실제 거리"를 한 번에 확인할 수 없어 길을 헤맨다.

## 2. 사용자 연구

### 2.1 인터뷰 개요

- 참여자: 캠퍼스에서 건물·강의실을 찾아본 경험이 있는 대학생 9명 (P1–P9)
- 방식: 반구조화 인터뷰. 헤맨 경험, 사용한 도구와 이유, 답답했던 점, 처음 확인한 정보, 예상과 다른 점, 대처 방법, 위치 정보 판단 기준, 도구 선택 기준 등을 물었습니다.
- 분석: 행동 유형에 따라 3개 페르소나로 묶었습니다 (아래 2.2).
- 연구의 한계: P7은 캠퍼스 밖(서면 맛집·카페) 사례를 중심으로 답했습니다. 참여자 수가 적어 정량적 결론은 내지 않고, 문제 발견과 설계 방향 도출에 활용했습니다.

| 구분 | 01 정확한 위치정보 확인형 | 02 건물 구조 파악형 | 03 주변 단서 활용형 |
|---|---|---|---|
| 대표 페르소나 | 김서윤 | 이도현 | 박지민 |

페르소나는 세 유형 모두 캠퍼스에서 길찾기에 어려움을 겪지만, 어려움을 느끼는 지점과 필요한 정보가 다르다는 점에서 구분됩니다. 따라서 하나의 유형만 위한 서비스로는 문제를 충분히 해결하기 어렵다고 보고 통합 서비스로 기획했습니다.

## 3. 서비스 개요

### 3.1 서비스 소개

**여기맞캠?**은 캠퍼스 안에서 "여기 맞아?"라는 순간에 바로 답해 주는 모바일 웹 서비스입니다. 이름은 길을 헤매다 멈춰 서서 "여기 맞아, 캠퍼스?"라고 묻는 말투에서 따왔습니다.

- **형태:** 모바일 웹앱. 설치 없이 링크나 QR로 바로 열 수 있어, 급할 때 빠르게 쓴다는 기준(P1, P4)과 접근성이 좋고 익숙한 것을 고른다는 기준(P2, P5)에 맞춥니다.
- **범위:** 여러 대학을 지원하는 구조로 설계하고, 첫 도입은 동의대학교로 합니다.

### 3.2 목표

- 처음 가는 장소를 찾을 때 현재 위치와 가야 할 방향을 한눈에 확인할 수 있게 한다.
- 건물 안(층·호수)과 건물 사이(연결 통로·지름길)를 하나의 안내로 이어 준다.
- 지도 위 정보를 주변 건물·랜드마크·실제 모습과 연결해 확신을 준다.

### 3.3 설계 원칙

| 원칙 | 내용 |
|---|---|
| 내 위치를 기준으로 안내 | 모든 안내는 지금 내가 있는 곳에서 시작합니다. 위치 권한이 없을 때는 사용자가 지도에서 고른 출발 위치를 기준으로 합니다. (P4, P6: 현재 위치에서 어느 방향으로 가야 하는지가 가장 중요) |
| 건물 안과 밖을 끊지 않는다 | 실외 경로와 실내 층 이동을 한 흐름으로 보여줍니다. (페르소나 02 디자인 시사점) |
| 주변 단서를 함께 보여준다 | 건물 이름과 번호보다 상대적인 랜드마크 위치, 실제 이동 거리를 함께 제공합니다. (페르소나 03 디자인 시사점) |
| 정보의 기준일을 밝힌다 | 건물·경로 정보의 확인 시점을 표시해 믿고 쓸 수 있게 합니다. (P6) |
| 시스템이 직접 답한다 | 커뮤니티나 질문 기능 없이, 정확한 데이터와 안내로 "사람에게 물어봐야 하는 상황" 자체를 줄입니다. (P1: 처음 물어본 사람도 모르는 경우) |

## 4. 핵심 기능 (MVP)

출시 버전에는 아래 네 가지 기능을 모두 넣습니다. 각 기능은 인터뷰에서 확인된 문제와 페르소나의 핵심 니즈에 대응합니다.

| 번호 | 기능 | 내용 | 대응 페르소나 | 해결하는 문제 |
|---|---|---|---|---|
| F1 | 내 위치·방향 + 목적지 방향 안내 | 현재 위치와 바라보는 방향을 지도에 표시하고, 목적지가 어느 쪽에 있는지 화살표와 거리로 보여줍니다. 현재 있는 건물이 목적지 건물인지도 바로 알려줍니다. | 01 | ① (P1, P4, P6) |
| F2 | 건물 내부 층별 지도 + 강의실 검색 | 건물명·호수로 강의실을 검색하면 층과 복도 위치를 층별 지도에 보여줍니다. 지하(B101 등)와 지상을 구분해 표기하고, 건물 입구 기준 이동 방향을 안내합니다. | 02 | ② (P3, P5, P8), ⑤ |
| F3 | 건물 간 연결 통로·지름길 경로 | 연결 다리, 붙어 있는 건물, 실내 지름길을 반영해 건물 사이 경로를 안내합니다. 층에 따라 연결 여부가 다른 경우(예: 4층만 연결 없음)도 반영합니다. | 02 | ③ (P5, P8), ① 일부 (P4, P6) |
| F4 | 주변 랜드마크·로드뷰 기반 안내 | 목적지 주변의 알려진 건물과 입구 사진을 보여주고, "○○관에서 걸어서 약 N분"처럼 랜드마크 기준 위치를 알려줍니다. 실제 이동 거리와 방향을 함께 제공합니다. | 03 | ④ (P2, P9), ⑤ |
| 공통 | 정보 기준일 표시 | 건물·경로 정보마다 마지막으로 확인한 날짜를 표시합니다. | 전체 | ⑥ (P6) |

### 우선순위와 제외 범위

- 네 기능 중 F1(위치·방향)을 안내의 뼈대로 두고, F2와 F3이 같은 경로 화면에서 이어지도록 설계합니다.
- 제외: 질문·답변 등 커뮤니티 기능, 친구에게 실시간 위치 공유. 이번 버전은 시스템 안내에 집중합니다.

## 5. 사용자 시나리오

*아래 시나리오는 인터뷰 사례를 바탕으로 만든 가상의 이야기입니다.*

### 시나리오 1. 김서윤 (01 정확한 위치정보 확인형)

- **상황:** 처음 가는 강의실이 있는 날, 서윤은 수업 시작 전에 "지금 내가 어디 있는지"부터 확인하고 싶습니다.
- **행동:** 여기맞캠?을 열고 강의실을 검색하면, 내 위치와 바라보는 방향, 목적지가 있는 쪽이 화살표로 표시됩니다 (F1).
- **결과:** 지금 서 있는 건물이 목적지 건물이 아니라는 것을 바로 알고, 사람에게 묻지 않고 이동을 시작합니다.

### 시나리오 2. 이도현 (02 건물 구조 파악형)

- **상황:** 건물은 찾았지만 강의실이 건물 어디에 있는지 모릅니다. 안내판만으로는 같은 층의 어느 방향인지 알 수 없습니다.
- **행동:** 강의실 호수를 검색해 층별 지도에서 복도 위치를 확인하고 (F2), 옆 건물로 넘어가야 하면 연결 통로 경로를 따라갑니다 (F3).
- **결과:** 109호 옆을 헤매는 대신 처음부터 돌아가야 하는 방향으로 이동합니다.

### 시나리오 3. 박지민 (03 주변 단서 활용형)

- **상황:** 평소 가지 않던 단과대 건물로 가야 하는데, 지도의 위치가 실제 풍경과 연결되지 않아 불안합니다.
- **행동:** 목적지 주변의 아는 건물과 입구 사진을 먼저 확인하고, "○○관에서 걸어서 약 N분"이라는 안내를 따라 이동합니다 (F4).
- **결과:** 아는 건물까지 먼저 찾아간 뒤 목적지로 이동하는 평소 방식을 그대로 이어 가며, 길을 헷갈려 처음으로 돌아가는 일이 줄어듭니다.

| 도착 완료 | 도착 안내, 홈으로, 정보 확인·제보 | 공통 |
| 정보 안내 | 각 정보의 기준일, 오류 제보 | 공통 |

화면 흐름: 앱을 열면 내 위치 지도에서 목적지 검색 → 목적지 확인 → (필요하면 주변 랜드마크 보기) → 경로 안내 → 건물 입구에서 층별 지도로 자동 전환 → 강의실 앞에서 도착 완료 자동 표시. 자동 전환이 안 되면 층별 지도 탭과 도착 확인 버튼을 직접 누를 수 있다. 정보 기준일은 목적지 확인, 경로 안내, 층별 지도에도 함께 보여준다.

## 7. 데이터 확보 및 운영 방안

캠퍼스 내부 정보는 일반 지도 앱에 없는 경우가 많아(P6, P8) 서비스의 성패는 데이터에 달려 있습니다. 확보 방식은 다음과 같이 정했습니다.

| 구분 | 내용 | 역할 |
|---|---|---|
| 기본 | 학교 건물 도면과 공공 데이터를 활용해 건물, 층, 호수, 입구 정보를 구축합니다. | 정확도의 기반 |
| 보완 | 사용자가 잘못된 정보나 새 지름길·연결 통로를 제보할 수 있게 합니다. | 현장 정보 보완 |
| 검수 | 운영진이 제보와 도면 정보를 확인한 뒤 반영하고, 확인한 날짜를 기록합니다. | 신뢰도 유지 |

### 도입 단계

- **1단계 (시범):** 동의대학교 일부 건물에서 도면 확보와 F1–F4 구현, 사용성 테스트
- **2단계:** 동의대학교 전체 캠퍼스 확대와 제보·검수 체계 운영
- **3단계:** 다른 대학으로 확장. 대학별로 도면·공공 데이터를 확보해 같은 구조에 추가

학교별 도면 제공 협조가 필요하므로, 시범 단계에서 학교 시설 담당 부서에 협조를 요청하는 것이 첫 과제입니다.

## 8. 기대 효과 및 검증 계획

### 기대 효과

- 처음 가는 장소에서 길을 헤매는 시간과 불안이 줄어듭니다.
- 건물 안과 건물 사이를 하나의 안내로 이어, 층·호수를 착각해 잘못 이동하는 경우가 줄어듭니다.
- 사람에게 묻거나 여러 앱을 오가던 행동을 한 서비스 안에서 해결할 수 있습니다.

### 검증 계획

아래 효과는 아직 검증되지 않은 가설이며, 시범 단계의 사용성 테스트로 확인합니다.

| 지표 | 측정 방법 |
|---|---|
| 목적지 도착 시간 | 처음 가는 강의실 찾기 과제를 주고 기존 지도 앱과 비교 |
| 오류 횟수 | 잘못된 건물·층으로 이동한 횟수 기록 |
| 확신도 | 과제 후 "위치를 확신하며 이동했는가" 5점 척도 설문 |
| 페르소나별 만족 | 01·02·03 유형 참여자를 각각 모집해 기능별 유용성 평가 |
