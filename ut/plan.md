# 사용성 평가 계획

서비스: 여기맞캠? (동의대 가야캠퍼스 길찾기) / 평가 화면: `design/prototype.html`
클로드 UT(`/ut-claude`)와 사람 UT에 같은 계획을 써요.

## 평가 목표
1. 처음 쓰는 사람이 사람에게 묻지 않고 목적지(제1인문관 401호)까지 길찾기를 끝내는지 확인한다.
2. 경로 안내(2.0)의 실내 지름길(중앙도서관·수덕전 엘리베이터로 5층)을 이해하고 따라갈 수 있는지 확인한다.
3. 층별 지도(2.2)에서 지금 층과 목적지 층, 방 위치(4층 왼쪽 끝)를 헷갈리지 않고 찾는지 확인한다.

### 평가가 끝나면 정할 것
1. 지름길 안내를 단계별 안내로 바꿀지 (지름길이 여러 개면 어느 길로 갈지 물어보기) → 과제 2
2. 층별 지도에 호실 이름을 작게 넣을지 → 과제 3
3. 자동 전환(입구에 오면 층별 지도로 바뀜)을 지금처럼 둘지, 바꿀지 → 과제 1

## 과제
### 과제 1: 처음 가는 강의실 찾기 (플로우 1, 김서윤) [핵심]
- 과제 문장: "지천관 앞 로터리 버스정류장에서 막 내렸어요. 다음 수업이 처음 가 보는 제1인문관 401호예요. 사람에게 묻지 않고 강의실까지 가 보세요."
- 시작 화면: 2.1 내 위치 지도
- 성공 기준: 2.4 도착 완료 화면에 도착
- 예상 단계 수: 5 (검색 → 길찾기 시작 → 길 고르기 → 층별 지도에서 층 확인 → 도착 확인). 길 고르기는 /ut-fix F2에서 생김
- 진행 메모: 참가자가 2.0에서 길을 읽고 나면 "갈림길 모습 보기"의 "입구 도착: 자동 전환"을 눌러 입구에 도착한 장면을 보여준다. 2.2에서 참가자가 강의실까지 가는 길을 말하면 "강의실 앞: 자동 전환"을 눌러 2.4로 보낸다 (2.2 기본 모습에는 도착 확인 버튼이 없음).
- 확인할 것: 자동 전환 흐름이 자연스러운지 (정할 것 3)

### 과제 2: 가장 빠른 길로 가기 (지름길)
- 과제 문장: "수업 시간이 빠듯해요. 로터리에서 제1인문관까지 더 빨리 가는 길이 있으면 그 길로 가 보세요. 어떻게 갈지 말로 설명해 주세요."
- 시작 화면: 1.1 목적지 확인
- 성공 기준: 2.0에 도착한 뒤 "중앙도서관(또는 수덕전) 엘리베이터로 5층에 올라가 5층 출입구로 나간다"고 설명함
- 예상 단계 수: 3 (길찾기 시작 → 길 고르기 → 안내 읽기)
- 진행 메모: 1.1에서 "길찾기 시작"을 누르면 "어느 길로 갈까요?" 창이 떠요 (2026-11-27 /ut-fix F2). 참가자가 지름길을 고르면 2.0이 그 길의 처음 모습으로 열린다. 참가자가 1번 단계를 읽고 나면 "갈림길 모습 보기"의 "지름길: 도서관 엘리베이터"(수덕전을 골랐으면 "지름길: 수덕전 엘리베이터")를 눌러 엘리베이터 앞 장면을 보여준다.
- 확인할 것: 배너 문구만 보고 길을 이해하는지, 지름길이 2개일 때 헷갈리는지 (정할 것 1)

### 과제 3: 건물 안에서 강의실 찾기 (플로우 2, 이도현)
- 과제 문장: "제1인문관 1층 입구로 막 들어왔어요. 401호가 몇 층 어디쯤 있는지 찾아서 그 앞까지 가 보세요."
- 시작 화면: 2.1 내 위치 지도
- 성공 기준: "4층 왼쪽 끝 계단 옆"이라고 말하고 2.4에 도착
- 예상 단계 수: 4 (검색 → 층별 지도 보기 → 4F 선택 → 도착 확인)
- 진행 메모: 시작 전에 1.1을 "갈림길 모습 보기"의 "지금 이 건물" 모습으로 바꿔 둔다. 2.2에서 참가자가 401호 위치를 말하면 "강의실 앞: 자동 전환"을 눌러 2.4로 보낸다.
- 확인할 것: 호실 이름 없이도 층별 지도에서 방 위치를 찾는지 (정할 것 2)

플로우 3(박지민)은 2.3 주변 랜드마크 화면이 아직 없어서 이번 평가에서 뺐다.

## 질문
- 사전 질문:
  1. "학교에서 처음 가는 건물이나 강의실을 찾을 때 주로 어떻게 하세요? 지도 앱, 안내판, 주변 사람에게 묻기 중에 무엇을 쓰는지, 왜 그걸 쓰는지 이야기해 주세요."
  2. "건물 안에서 층이나 호수를 헷갈려 헤맨 적이 있나요? 그때 어떻게 하셨어요?"
- 과제마다: "이 과제는 얼마나 쉬웠나요? 1(아주 어렵다)부터 5(아주 쉽다)까지 골라 주세요."
- 사후 질문:
  1. "오늘 써 보면서 가장 헷갈렸던 곳은 어디였나요?"
  2. "가장 좋았던 곳이나 도움이 됐던 곳은 어디였나요?"
  3. "학교에서 길을 찾을 때 이 서비스를 쓸 것 같나요? 왜 그렇게 생각하세요?"

## 참가자 조건 (사람 UT)
3명. 퍼소나(김서윤, 이도현, 박지민)마다 비슷한 사람을 한 명씩 찾는다.
1. 동의대 가야캠퍼스 학생이고, 제1인문관에 가 본 적이 없거나 거의 없는 사람
2. 최근 한 학기 안에 처음 가는 건물이나 강의실을 찾아 헤맨 적이 있는 사람
3. 스마트폰 지도 앱을 써 본 적이 있는 사람

- 우리 팀원, 이 서비스를 이미 본 사람은 안 된다.
- 참가자 이름은 기록하지 않고 P1, P2, P3 처럼 번호로 적는다.

## 진행 대본
준비: 화면 아래 "갈림길 모습 보기"는 진행자용이에요. 참가자가 누르지 않도록 손으로 가리거나 미리 말해 둔다. 휴대폰(또는 노트북 브라우저 창을 휴대폰 크기로)에 `design/prototype.html` 을 2.1 화면으로 열어 둔다. 관찰 기록지(`ut/sheet.md`)를 참가자 번호로 복사해 둔다. 진행 1명, 기록 1명.

1. 인사
   > "안녕하세요, 시간 내 주셔서 고마워요. 오늘은 저희가 만든 캠퍼스 길찾기 서비스 '여기맞캠?'을 써 보시는 모습을 볼 거예요. 오늘 평가하는 건 서비스이지 ○○님이 아니에요. 틀린 답은 없고, 헤매셨다면 그건 저희 화면이 고쳐야 할 곳이에요. 20분쯤 걸려요."
2. 동의
   > "진행하는 동안 메모를 남겨도 될까요? 이름은 적지 않고 번호로만 기록해요. 중간에 그만두고 싶으면 언제든 말씀해 주세요."
3. 소리 내어 생각하기 설명
   > "화면을 보면서 떠오르는 생각을 그대로 말로 해 주세요. '이게 뭐지?', '여기를 누르면 될 것 같은데' 같은 말이면 돼요. 이 화면은 실제로 걸어 다니며 쓰는 건 아니라서, 걸어가는 장면은 제가 화면을 바꿔서 보여드릴게요. 그때도 실제로 걷고 있다고 생각하고 써 주세요."
4. 사전 질문
   > "시작하기 전에 두 가지만 여쭤볼게요." (사전 질문 1, 2)
5. 과제 하나씩 읽어 주기
   > "이제 상황을 하나씩 읽어 드릴게요. 그 상황이라고 생각하고 화면을 써 주세요."
   - 과제 문장을 그대로 읽는다. 화면이나 버튼 이름으로 바꿔 말하지 않는다.
   - 진행하는 사람은 도와주지 않는다. 막히면 "어떻게 하실 것 같아요?" 만 묻는다.
   - 과제 1: 참가자가 2.0에서 안내를 읽고 나면 "이제 제1인문관 입구에 도착했어요" 라고 말하고 "입구 도착: 자동 전환"을 눌러 준다.
   - 과제 2: 1.1에서 "어느 길로 갈까요?" 창이 뜨면 참가자가 스스로 고르게 둔다. 2.0에서 1번 단계를 읽고 나면 "이제 그 건물 앞에 왔어요" 라고 말하고 고른 길의 "지름길: ○○ 엘리베이터"를 눌러 준다.
   - 과제 3: 시작 전에 1.1을 "지금 이 건물" 모습으로 바꿔 둔다.
   - 3분 넘게 막히면 "좋아요, 이 과제는 여기까지 할게요" 라고 하고 다음 과제로 넘어간다.
6. 과제마다 쉬움 점수 묻기
   > "이 과제는 얼마나 쉬웠나요? 1(아주 어렵다)부터 5(아주 쉽다)까지 골라 주세요."
   과제가 끝날 때마다 2.1 화면으로 돌려 놓는다.
7. 사후 질문, 감사 인사
   > "마지막으로 세 가지만 여쭤볼게요." (사후 질문 1~3)
   > "오늘 정말 고마워요. 말씀해 주신 내용으로 서비스를 고칠게요."

기록은 `ut/notes/P1.md`, `P2.md`, `P3.md` 로 저장한다.
